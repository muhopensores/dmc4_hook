macro*.txt Script Reference#

This is the complete lookup reference for Macro. For installation, a first macro, controller explanations, Battle Snapshot, and common workflows, open Find What You Need in the Player Guide.

Use the page contents or browser search to jump directly to an input name, command, condition, or error. This page is a lookup manual, not the best first reading order.

Syntax At A Glance#

A playable clip:

[V][Nero] Example
TAP MELEE
WAIT 10
TAP JUMP

The key distinction is whether a word is an input name or a complete command.

Can this be pressed, held, and released like controller input? If yes, use an input command. If the whole line already describes timing or Hook behavior, write the complete command by itself.

Clip Headers And File Structure#

Header formats:

[KeyboardHotkey][Character] Clip name
[KeyboardHotkey][GamepadButton][Character] Clip name
[KeyboardHotkey][SWITCH] Clip name
[KeyboardHotkey][GamepadButton][SWITCH] Clip name

Examples:

[V][Nero] Nero test
[V][X/SQUARE][Nero] Nero test with controller shortcut
[F2][A][Nero] Nero test with one Xbox button name
[F3][CIRCLE][Dante] Dante test with one PlayStation button name
[V][Dante] Dante test
[F1][RB/R1][Dante] Dante route with controller shortcut
[Ctrl+1][Nero] Boss route
[F9][SWITCH] Character Switcher route

File rules:

  • blank lines are ignored
  • text after # or ; is a comment
  • write one command per line
  • playback commands must be inside a clip; Setup fields belong inside [Setup] ... [/Setup]
  • use [Nero] or [Dante] for ordinary single-character clips
  • use [SWITCH] when action names must follow the current character after CHARACTER_SWITCH
  • the optional middle gamepad tag is the second button after the fixed Back/Select prefix
  • clip hotkeys start that specific clip; GUI action hotkeys run the currently selected file and clip
  • Macro injects DMC4 controller input, not Windows keyboard events

Each clip may contain up to 600000 generated playback frames. WAIT 100 adds 100 frames and TAP MELEE 20 adds 20. Combining several inputs with + does not multiply that count. WAIT_UNTIL uses one generated wait frame whose condition is evaluated at runtime. Normal combo scripts are unlikely to approach this limit.

Character must be Nero or Dante. Short tags N and D are accepted, but full names are clearer.

The same keyboard hotkey may be used once for Nero and once for Dante. Duplicate hotkeys for the same character are rejected. A [SWITCH] clip can start as either character, so it cannot share the same keyboard or gamepad clip hotkey with an ordinary Nero/Dante clip.

Gamepad header buttons include face buttons, bumpers, triggers, stick clicks, Start/Options, and D-pad directions. Back/Select itself is reserved as the prefix.

A gamepad header tag may contain one accepted Xbox or PlayStation name. Equivalent examples are:

[A]       = [CROSS]       = [A/CROSS]
[B]       = [CIRCLE]      = [B/CIRCLE]
[X]       = [SQUARE]      = [X/SQUARE]
[Y]       = [TRIANGLE]    = [Y/TRIANGLE]
[LT]      = [L2]          = [LT/L2]

The slash form is optional and exists only so a header can show aliases from both controller layouts. If slash names are used, every part must describe one physical button:

[A]      valid
[CIRCLE] valid
[L2/LT]  valid
[LT/L2]  valid
[L2/LB]  invalid

With Gamepad Hotkeys enabled, hold Back/Select first, then press the header's gamepad button. Macro consumes the detected shortcut so DMC4 does not also receive it.

Keyboard hotkeys support:

Hotkey typeExamples
Single letters or numbersV, 1, Z
Function keysF1 through F24
Numpad keysNUMPAD0 through NUMPAD9
Modifier combinationsCtrl+1, Shift+V, Alt+F2, Ctrl+Shift+F5
Named keysSpace, Tab, Enter, Esc, Backspace, Insert, Delete, Home, End, PageUp, PageDown, arrow keys

How Macro Lines Run#

Macro runs from top to bottom until the clip ends:

HOLD LOCK_ON
HOLD MOVE_LEFT
TAP MELEE
WAIT 10
RELEASE MOVE_LEFT
TAP JUMP
WAIT_UNTIL GROUNDED
RELEASE LOCK_ON

There is no rule that only one command may appear between two waits. Consecutive HOLD, RELEASE, complete commands, or TAP lines are valid.

WAIT ticks delays the following line. WAIT_UNTIL condition [max_ticks] continues when the condition succeeds or its timeout expires. Omitted max_ticks defaults to 120.

TAP sends input; it does not wait for the resulting move or animation to finish.

HOLD remains active through later lines and waits until a matching RELEASE, RELEASE ALL, CLEAR, SET, or Stop Macro removes it.

A script line is not automatically a time step. These commands add generated playback frames:

CommandPlayback time
TAP input [ticks]Adds ticks frames. Default is 1.
WAIT ticksAdds ticks frames using the current held input state.
WAIT_UNTIL condition [max_ticks]Adds one conditional wait frame that stays active until success or timeout.
DIR ...Adds temporary direction/action frames.
BACK_FORWARD ...Adds the back, forward, and action frames.
Complete Hook commandsUsually add one command frame, such as CHARACTER_SWITCH or FREEZE.

These commands change the held input state but do not create playback time by themselves:

CommandEffect
HOLD inputAdds input to the held state.
RELEASE inputRemoves input from the held state.
SET inputClears held state, then holds the supplied input.
CLEARClears held state.

Combining Inputs With +#

Use + when several inputs belong to one command:

TAP JUMP+MELEE
HOLD LOCK_ON+MOVE_LEFT+GUN
RELEASE LOCK_ON+MOVE_LEFT+GUN
SET LOCK_ON+MOVE_BACK+MELEE

Rules:

  • + means simultaneous input.
  • There is no fixed two-input or three-input limit.
  • Every part must be a valid input name for the clip.
  • Multi-input TAP must use +; TAP JUMP MELEE is invalid because the second argument position is reserved for tap duration.
  • TAP JUMP+MELEE 20 holds both inputs together for 20 input ticks.
  • Separate TAP lines are sequential. Add WAIT only when you need a larger gap.
# Simultaneous
TAP JUMP+MELEE

# Jump for one tick, then melee on the next tick
TAP JUMP
TAP MELEE

# Jump, wait ten ticks, then melee
TAP JUMP
WAIT 10
TAP MELEE

TAP A+B is roughly equivalent to:

HOLD A+B
WAIT 1
RELEASE A+B

TAP A+B 20 is roughly equivalent to:

HOLD A+B
WAIT 20
RELEASE A+B

The difference is that TAP restores the held input state that existed before the tap. A manual RELEASE A+B removes those inputs from the held state.

Different left-stick axes create a diagonal:

HOLD MOVE_FORWARD+MOVE_RIGHT

Opposite directions cancel and should not be combined:

HOLD MOVE_LEFT+MOVE_RIGHT
HOLD MOVE_FORWARD+MOVE_BACK
HOLD CAM_LEFT+CAM_RIGHT

Avoid combining full and slow movement in opposite directions, such as MOVE_RIGHT+WALK_LEFT; their analog values are added and the result is usually not what the script author intended.

The + in [Ctrl+1][Nero] belongs to a keyboard hotkey. The + in TAP JUMP+MELEE combines game inputs.

Input Names#

Input names describe a controller action, physical button, stick direction, camera direction, or D-pad direction. They do not do anything by themselves. Use them after commands such as TAP, HOLD, RELEASE, SET, DIR, or BACK_FORWARD.

Character Action Names#

Action names mean "press the button assigned to this action in the GUI Action Mapping table." They are usually the best choice for shared scripts because they follow each player's controller layout.

They also make scripts easier to read. TAP MELEE or TAP DEVIL_TRIGGER describes the intended game action, so the script usually needs fewer comments than a physical-button-only version such as TAP Y or TAP LB.

Nero and Dante have separate Action Mapping tables. The clip header chooses the table:

[V][Nero]  uses Nero Action Mapping
[V][Dante] uses Dante Action Mapping

For Character Switcher clips, use [SWITCH] when action names should follow the current character during playback:

[V][SWITCH] Switch route
CHARACTER_SWITCH
WAIT 20
TAP STYLE_ACTION

This clip can start as Nero or Dante. After Character Switcher changes the active character, later action names are resolved through that current character's Action Mapping. Use a WAIT or another condition after CHARACTER_SWITCH; the switch is requested by the hook and is not guaranteed to be usable on the same tick.

Shared action names are accepted by both characters. The script word is the same, but the output button is read from that character's table:

[F1][Nero] Nero melee
TAP MELEE

[F1][Dante] Dante melee
TAP MELEE

If Nero Action Mapping has MELEE = Y / TRIANGLE and Dante Action Mapping has MELEE = B / CIRCLE, the Nero clip presses Y / TRIANGLE and the Dante clip presses B / CIRCLE.

Character-only action names are different. EXCEED and BRINGER only make sense in [Nero] clips. STYLE_ACTION, CHANGE_GUN, and CHANGE_SWORD only make sense in [Dante] clips. If an action is not valid for the clip's character, the macro file will fail to load that line.

Action Mapping can point an action to face buttons, bumpers, triggers, stick clicks, Back/Select, Start/Options, or D-pad directions. If your DMC4 controller settings put an action on D-pad, choose the same D-pad direction in the matching Nero or Dante Action Mapping table.

Physical button names do not use Action Mapping. TAP Y always presses Y / TRIANGLE, even if Nero or Dante melee is set to B / CIRCLE in DMC4. TAP MELEE presses the mapped melee button for the header character, or for the current character in a [SWITCH] clip.

  • Shared names such as MELEE can map to different buttons for Nero and Dante.
  • For new shared scripts, prefer the main action name in the first column. The alias column is mainly for reading older scripts.

Detailed Command Reference#

Commands are complete script lines. Some commands take input names as arguments, and some commands run built-in macro or hook behavior by themselves.

Input Commands#

These commands use the input names from the previous section.

TAP#

TAP input
TAP input ticks

Examples:

TAP MELEE
TAP JUMP
TAP EXCEED
TAP MELEE 3
TAP LOCK_ON+MELEE 2

If ticks is omitted, the tap lasts 1 input tick.

All items joined by + are pressed during the same tap. There is no fixed limit of two or three inputs:

TAP A+B+X+Y
TAP LOCK_ON+MOVE_LEFT+MELEE+DEVIL_TRIGGER 2

The practical limit is whether every name is valid and whether the combination makes sense to DMC4. Opposite analog directions cancel.

TAP A+B behaves like a one-tick temporary hold:

HOLD A+B
WAIT 1
RELEASE A+B

TAP A+B 20 behaves like a 20-tick temporary hold:

HOLD A+B
WAIT 20
RELEASE A+B

The exact implementation temporarily adds the tap input to the current held state, writes the requested playback frames, then restores the previous held state. This matters when one of the tapped inputs was already held before the TAP.

HOLD#

HOLD input
HOLD input+input

Alias:

PRESS input

Examples:

HOLD LOCK_ON
HOLD MOVE_LEFT
HOLD LOCK_ON+MOVE_LEFT

Held input remains active through later WAIT lines until released, cleared, or stopped.

HOLD accepts more than two combined inputs:

HOLD LOCK_ON+MOVE_FORWARD+GUN+DEVIL_TRIGGER

Consecutive HOLD lines do not spend time by themselves. They combine before the next frame-producing command:

HOLD MELEE
HOLD JUMP
WAIT 1

is equivalent to:

HOLD MELEE+JUMP
WAIT 1

RELEASE#

RELEASE input
RELEASE input+input
RELEASE ALL

Alias:

REL input

Examples:

RELEASE MELEE
RELEASE LOCK_ON+MOVE_LEFT
RELEASE ALL

SET#

SET clears the current macro-held state, then holds the new input.

SET LOCK_ON+MOVE_LEFT
WAIT 5
RELEASE ALL

CLEAR#

CLEAR stops holding all macro-held input.

CLEAR

DIR#

DIR direction action ticks

Alias:

DIRECTION direction action ticks

Temporarily holds a direction and an action, then releases only those inputs.

HOLD LOCK_ON

Character Switcher#

These are complete command lines:

CHARACTER_SWITCH
SWITCH_CHARACTER

Aliases:

CHAR_SWITCH
CHARACTER_SWAP
SWAP_CHARACTER

This requests one Character Switcher swap. It does not enable Character Switcher by itself.

Requirements:

  • enable Character Switcher in the hook GUI before entering the stage
  • wait until both characters have been created by Character Switcher
  • do not use it in missions or moments where Character Switcher itself is unsafe

If Character Switcher is not enabled or ready, the command does nothing and the Macro status line reports it.

By default, a clip keeps using the header character's Action Mapping for the whole playback. If a script switches characters and then uses action names for whichever character is current, use a [SWITCH] header:

[V][SWITCH] Switch action route
CHARACTER_SWITCH
WAIT 20
TAP STYLE_ACTION

Without [SWITCH], a normal [Nero] or [Dante] clip keeps resolving action names through its header character after the switch.

Hook Actions#

One Hit Kill:

OHK TOGGLE

Aliases:

ONEHITKILL ON

ON enables One Hit Kill, OFF disables it, and TOGGLE flips the current setting. ENABLE, ENABLED, TRUE, and 1 also mean on. DISABLE, DISABLED, FALSE, and 0 also mean off.

Timing And Conditional Wait#

WAIT#

WAIT n uses DMC4 input ticks, not milliseconds.

HOLD MELEE
WAIT 1
RELEASE MELEE

This is the normal fastest long-form tap. Without WAIT 1, the game may not see the input as held.

One tick is one pass through DMC4's input update path. In normal play it is usually close to one rendered frame.

WAIT_UNTIL#

WAIT_UNTIL pauses macro playback until a game state becomes true, then continues on the same script.

WAIT_UNTIL condition [max_ticks]
WAIT_UNTIL ANIM_FRAME [operator] frame [max_ticks]
WAIT_UNTIL MOVEID2 [operator] value [max_ticks]

Aliases:

WAITUNTIL
UNTIL

If the condition becomes true earlier, playback continues immediately. max_ticks is a safety timeout measured in input ticks. If max_ticks is omitted, it defaults to 120. While a macro is waiting, earlier HOLD inputs stay held until the script reaches RELEASE, RELEASE ALL, CLEAR, or the macro is stopped.

How to read these templates:

  • Words such as condition, operator, frame, value, and max_ticks are placeholders. Replace them with real script text.
  • Square brackets mean optional. For example, [max_ticks] means you may write a timeout such as 180, or leave it out to use the default 120.
  • WAIT_UNTIL condition [max_ticks] is for simple yes/no conditions such as GROUNDED, CAN_EXCEED, HITSTOP, or LOCKED_ON.
  • WAIT_UNTIL ANIM_FRAME [operator] frame [max_ticks] waits for the current Frame number shown by Animation Overlay.
  • WAIT_UNTIL MOVEID2 [operator] value [max_ticks] waits for the current MoveID2 shown by Animation Overlay. Decimal and hex values are both accepted.

Comparison Operators#

Comparison operators are supported for ANIM_FRAME and MOVEID2:

==  !=  >  >=  <  <=

These signs mean:

SignHow to read itExample meaning
==equalsMOVEID2 == 30 means "MoveID2 is exactly 30".
!=does not equalMOVEID2 != 30 means "MoveID2 is anything except 30".
>greater thanANIM_FRAME > 28 means "frame is later than 28".
>=greater than or equal toANIM_FRAME >= 28 means "frame has reached 28 or later".
<less thanANIM_FRAME < 28 means "frame is still before 28".
<=less than or equal toANIM_FRAME <= 28 means "frame is 28 or earlier".

Word spellings such as EQ, NOT_EQUAL, GREATER_THAN_OR_EQUAL, and LESS_THAN_OR_EQUAL are also accepted, but the signs are shorter.

ANIM_FRAME compares the current runtime animation frame as a decimal number. If the operator is omitted, it defaults to >=:

WAIT_UNTIL ANIM_FRAME 28 120
TAP MELEE

This is the same as:

WAIT_UNTIL ANIM_FRAME >= 28 120
TAP MELEE

It means: wait until the shown animation frame reaches 28 or later. If that does not happen within 120 input ticks, continue anyway.

MOVEID2 compares the runtime value shown by Animation Overlay. If the operator is omitted, it defaults to ==:

WAIT_UNTIL MOVEID2 0x0000001E 120
TAP JUMP

This is the same as:

WAIT_UNTIL MOVEID2 == 0x0000001E 120
TAP JUMP

It means: wait until the shown MoveID2 is exactly 0x0000001E. If that does not happen within 120 input ticks, continue anyway.

Decimal values also work:

WAIT_UNTIL MOVEID2 == 30 120

MOVEID2_CHANGED captures the current MoveID2 when the wait begins and continues after it changes. Put it after the command that starts the action you want to leave:

TAP MELEE
WAIT_UNTIL MOVEID2_CHANGED 120
TAP MELEE

FRAME_REACHED_MAX checks whether animFrame has reached the runtime animFrameMax value. This is a frame display condition, so confirm the result in-game when using it to time the next action.

Recommended tuning workflow:

  1. Turn on Animation Overlay.
  2. Perform the action manually or play the macro once.
  3. Note the displayed Frame and MoveID2 values at the moment you want.
  4. Add the matching WAIT_UNTIL condition to the script.
  5. Use a larger timeout such as 180 or 240 while tuning longer actions if the default 120 is too short.

Macro Setup Blocks#

A macro file may contain one [Setup] block before the clip sections. Macro Setup is a separate practice workflow from Battle Snapshot.

Basic layout:

[Setup]
Character Nero
Room BP 4
Player 120.0 0.0 -80.0 Face 90
Camera Pos 10.0 250.0 -300.0 Target 100.0 80.0 -50.0 Fov 45
Enemy 1 Frost Pos 200.0 0.0 -60.0 Face 180
Enemy 2 Frost Pos 260.0 0.0 -30.0 Face 180
[/Setup]

[F1][Nero] Frost combo test
TAP MELEE

Rules:

  • Put [Setup] before all macro clips.
  • End it with [/Setup].
  • Only one setup block is supported per file.
  • A Setup-only file with no clip sections is valid for Load Setup.
  • Copy Current Setup copies a setup block from the current scene.
  • Load Setup prepares the selected macro file's setup without playing a clip.
  • Load Setup + Play Macro prepares the setup, waits Setup Play Delay Ticks, then starts the selected clip.
  • Play Macro and Load Setup + Play Macro require at least one clip.
  • Battle Snapshot buttons always use the captured Battle Snapshot. They do not inspect [Setup].
  • Setup can switch to the requested character and load the requested room.
  • Setup waits for native room enemies, then generates missing enemy types through the Hook's Enemy Spawn feature.
  • Existing matching enemies are reused. Extra enemies are not removed.
  • Setup then repositions the player, matched enemies, and camera.
  • Copy Current Setup skips dead enemies and cleanup objects that are no longer valid battle targets.
  • A failed character switch, room load, or enemy spawn stops Setup and prevents playback.

Common Script Misunderstandings#

  • Input names alone do nothing. Write TAP MELEE, not just MELEE.
  • WAIT is not a section separator. You can place several commands before or after one WAIT.
  • + combines inputs for one command. It does not mean "do the left input, then the right input."
  • + is not limited to two inputs. Longer combinations are valid when every item is a valid input.
  • Multi-input TAP lines need +. Write TAP JUMP+MELEE, not TAP JUMP MELEE.
  • Opposite stick directions cancel. Do not combine MOVE_LEFT+MOVE_RIGHT, MOVE_FORWARD+MOVE_BACK, or CAM_LEFT+CAM_RIGHT.
  • [Ctrl+1] is a keyboard hotkey. JUMP+MELEE inside an input command is simultaneous game input.
  • TAP does not wait for a move to finish. It only sends the input, then the next macro line may run.
  • HOLD does not release by itself. Release it later, clear macro input, or stop the macro.
  • RELEASE only releases macro-held input. It does not cancel a game action that already started.
  • Action names and physical buttons are different. TAP MELEE follows the clip character's Action Mapping, or the current character in a [SWITCH] clip. TAP Y always presses the physical Y / TRIANGLE button.
  • Movement names are left-stick directions. MOVE_LEFT is not the keyboard A key; LEFT is D-pad Left.
  • Camera names are right-stick movement. CAM_LEFT or RS_LEFT moves the camera; RS is the right-stick click button.
  • CHANGE_STYLE_RG is only a readable alias for D-pad Down. It does not inspect Dante's controller settings or force Royalguard.
  • The gamepad tag in a header, such as [F1][X/SQUARE][Nero], is a clip shortcut. It is not the first input line of the script.

Error And Troubleshooting Index#

  • Invalid token: check spelling, character tag, and Action Mapping validity, then save the macro file so it auto-reloads.
  • Line X: section header must include [Nero], [Dante], or [Switch]: add a character mode after the hotkey.
  • Action names are wrong after CHARACTER_SWITCH: use a [SWITCH] header, for example [V][SWITCH], and wait briefly after CHARACTER_SWITCH.
  • Line X: invalid HOLD/TAP/RELEASE input: the input name is misspelled or not valid for the clip's character.
  • Macro file is too long or TAP input is invalid: check that multi-input TAP uses +, that the optional final argument is a number, and that every action is valid for the clip character.
  • Macro file is too long: the clip exceeded 600000 generated playback frames. Reduce very long WAIT or TAP ... ticks ranges.
  • Exceed becomes the wrong action: make sure the clip header is [...][Nero], use EXCEED, and set Nero Action Mapping EXCEED to your in-game Exceed button.
  • TAP L2 behaves differently from TAP EXCEED: L2 is the physical trigger; EXCEED is the Nero action name.
  • Camera does not move: use CAM_LEFT / RS_LEFT, not plain RS.
  • Target does not change: use CHANGE_TARGET while locked on, and make sure the clip's Nero/Dante Action Mapping table matches your in-game controller settings.
  • Directional move comes out on the wrong side: swap MOVE_LEFT and MOVE_RIGHT, or swap MOVE_FORWARD and MOVE_BACK.
  • WAIT_UNTIL continues too early or too late: write an explicit timeout, confirm the value with Animation Overlay, and check whether the condition is for Nero, Dante, grounded state, hitstop, or Enemy Step range.
  • Macro Setup cannot load a BP floor: enter Bloody Palace first.
  • Macro Setup cannot load a room: confirm that the Room ID exists in the Hook's Area Jump list.
  • Macro Setup cannot generate an enemy: the current Enemy Spawn feature does not support that type. Existing matching enemies can still be used.
  • Battle Snapshot refuses to load: the captured room, player, camera, encounter, or enemy lifecycle no longer matches. Return to the original setup or capture again.

After an unhandled crash, send the matching folder from:

Devil May Cry 4\dmc4_hook_crashes\<timestamp_pid>\

Include what you were doing, the selected macro file and clip, and whether Macro, Character Switcher, Snapshot, or Area Jump was enabled.
