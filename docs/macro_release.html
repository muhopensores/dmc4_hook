DMC4 Macro + Battle Snapshot Player Guide#

Use this guide to run your first macro, understand controller inputs, and choose a repeatable practice workflow. New players can begin with the steps below and open the detailed sections only when they need them.

Quick Start#

  1. Put dinput8.dll and macro.txt next to DevilMayCry4_DX9.exe. See Install for download links and details.
  2. Open the Hook GUI, go to Training -> Macro, enable Macro, and make sure Nero Action Mapping -> JUMP matches Nero's Jump button in DMC4.
  3. Put the clip below in macro.txt, save the file, select Jump test in the GUI, play as Nero, and press V.
[V][Nero] Jump test
TAP JUMP
Nero should jump once. If another action happens, fix Nero Action Mapping first. TAP JUMP follows that mapping; a physical name such as TAP A always presses A / Cross.

Macro is an automatic controller note sheet: it reads a clip from top to bottom and sends DMC4 controller input. It does not send Windows keyboard events. Continue with Ten-Minute First Macro to add waits, held inputs, simultaneous inputs, and an optional controller shortcut.

Install#

Required files:

  • dinput8.dll from the latest official Hook release
  • macro.txt starter template, or a new plain-text file with that name
  • macro.txt, macro_release.html, and macro_script_reference.html kept together if you want their links to work offline
  1. Close the game.
  2. Back up the existing dinput8.dll next to DevilMayCry4_DX9.exe.
  3. Copy the new dinput8.dll next to DevilMayCry4_DX9.exe.
  4. Copy macro.txt to the same folder.
  5. Launch the game and open the dmc4_hook GUI.
  6. Enable Macro under Training.

The GUI automatically lists files next to the game executable whose names begin with macro and end with .txt:

macro.txt
macro_nero.txt
macro_boss_practice.txt

Use Custom Macro File when the file is stored somewhere else.

Ten-Minute First Macro#

Before testing action names, open Training -> Macro -> Nero Action Mapping and match JUMP, MELEE, and LOCK_ON to Nero's current DMC4 controller settings. Action names follow this table; physical button names such as A or Y do not.

Create or edit macro.txt:

[V][Nero] Jump test
TAP JUMP

Controller shortcut version:

[V][A/CROSS][Nero] Jump test
TAP JUMP

This header means:

PartMeaning
[V]Press V to start this clip.
[A/CROSS]Optional controller shortcut button. Hold Back/Select first, then press A / Cross.
[Nero]Resolve action names through Nero Action Mapping.
Jump testThe name shown in the GUI clip list.
TAP JUMPPress the action mapped as Jump once.

In game:

  1. Enable Macro.
  2. Select macro.txt.
  3. Select the Jump test clip.
  4. Play as Nero.
  5. Press V or click Play Macro.

Nero should jump once.

If you used the controller shortcut version, also enable Gamepad Hotkeys, then hold Back/Select first and press A / Cross. Pressing A / Cross first will not trigger the shortcut. While Gamepad Hotkeys is enabled, Back/Select is reserved by Macro shortcuts and will not trigger its normal in-game action manually.

For Dante, change the header to:

[V][Dante] Jump test
TAP JUMP

Now add a second action:

[V][Nero] Jump and attack
TAP JUMP
WAIT 10
TAP MELEE

WAIT 10 does not mean "wait for the jump animation to finish." It means Macro waits 10 input ticks before sending the next line. If the attack is too early or too late, change the number and test again.

Now try holding and releasing an input:

[V][Nero] Lock-on attack
HOLD LOCK_ON
TAP MELEE
WAIT 20
RELEASE LOCK_ON

HOLD LOCK_ON keeps Lock-On active through later lines. It stays active until RELEASE LOCK_ON, RELEASE ALL, CLEAR, SET, Stop Macro, or the end-of-playback cleanup removes it.

Finally, try a same-tick combination:

[V][Nero] Jump attack
TAP JUMP+MELEE

+ means the inputs are sent together in one command. This is different from two separate TAP lines.

When a macro does not do what you expected, enable Show Macro Playback Overlay. Check:

  • Now: the current script line
  • Next: the next script line
  • Held: inputs that Macro is still holding
  • Progress: where playback is in the clip

The Input Rule#

The most important rule is:

If a word represents something that can be pressed, held, or released on a controller, put it after TAP, HOLD, RELEASE, or SET.
If the whole line already means wait, switch character, freeze the screen, or run another Hook action, do not add TAP.
What it representsCorrect lineWhy
Character actionTAP MELEEMELEE is an input resolved through Action Mapping.
Physical buttonTAP YY is the exact Y / Triangle button.
Left-stick directionHOLD MOVE_LEFTThe virtual left stick stays pushed left.
Right-stick directionHOLD CAM_LEFTThe virtual right stick stays pushed left.
Stick clickTAP LSThis presses the left stick button / L3.
D-pad directionTAP DOWNThis presses D-pad Down.
Wait commandWAIT 10The line is already a complete timing command.
Character SwitcherCHARACTER_SWITCHThe line requests a Hook character switch.
Screen FreezeFREEZEThe line is already a complete Hook command.

Wrong:

MELEE
MOVE_LEFT
TAP CHARACTER_SWITCH

Right:

TAP MELEE
HOLD MOVE_LEFT
CHARACTER_SWITCH

Buttons And Sticks#

Players often use the word "stick" for several different inputs. The script names keep them separate:

NameMeaning
MOVE_LEFTPush the virtual left stick left.
WALK_LEFTLightly push the virtual left stick left.
CAM_LEFTPush the virtual right stick left.
LS / L3Press the left stick button.
RS / R3Press the right stick button.
LEFT / DPAD_LEFTPress D-pad Left.

Examples:

# Move for 30 ticks
HOLD MOVE_FORWARD
WAIT 30
RELEASE MOVE_FORWARD

# Move the camera
HOLD CAM_LEFT
WAIT 20
RELEASE CAM_LEFT

# Press the left stick button
TAP LS

# Press D-pad Left
TAP LEFT

Movement and camera names are controller-stick inputs. They are not keyboard keys.

Combining Inputs With +#

Use + when several inputs must belong to the same command:

TAP JUMP+MELEE
HOLD LOCK_ON+MOVE_LEFT+GUN
RELEASE LOCK_ON+MOVE_LEFT+GUN
SET LOCK_ON+MOVE_BACK+MELEE

Important rules:

  • + means simultaneous input, not "then".
  • You may combine more than two inputs. There is no fixed two-input or three-input limit.
  • Every part must still be a valid input name for the clip.
  • Multi-input TAP lines must use +.
  • Use separate TAP lines when inputs should happen in sequence. Add WAIT only when you need a bigger gap.

Simultaneous:

TAP JUMP+MELEE

Sequential:

TAP JUMP
TAP MELEE

This sends JUMP for one input tick, then MELEE for one input tick on the next macro tick.

Add a gap:

TAP JUMP
WAIT 10
TAP MELEE

TAP JUMP+MELEE 20 holds both inputs together for 20 input ticks, then releases both.

TAP A+B is roughly the same as:

HOLD A+B
WAIT 1
RELEASE A+B

TAP A+B 20 is roughly the same as:

HOLD A+B
WAIT 20
RELEASE A+B

The small difference is that TAP temporarily adds its inputs and then restores whatever was already held before the tap. A manual RELEASE A+B will release those inputs even if one of them was already held earlier.

Different left-stick axes can make a diagonal:

HOLD MOVE_FORWARD+MOVE_RIGHT

Opposite directions cancel each other and should not be combined:

HOLD MOVE_LEFT+MOVE_RIGHT
HOLD MOVE_FORWARD+MOVE_BACK
HOLD CAM_LEFT+CAM_RIGHT

Do not confuse script input combinations with keyboard hotkeys. In [Ctrl+1][Nero], Ctrl+1 is a keyboard shortcut. In TAP JUMP+MELEE, JUMP+MELEE is simultaneous game input.

Macro Clips#

Each playable clip begins with a header:

[KeyboardHotkey][Character] Clip name
[KeyboardHotkey][GamepadButton][Character] Clip name

Examples:

[V][Nero] Nero route
[V][Dante] Dante route
[F1][X/SQUARE][Nero] Nero route with controller shortcut
[F2][A][Nero] Nero route using one Xbox button name
[F3][CIRCLE][Dante] Dante route using one PlayStation button name

The same keyboard hotkey may be used once for Nero and once for Dante. Macro chooses the clip matching the current character.

Character Tags And Action Mapping#

Nero and Dante have separate controller settings. The character tag selects the corresponding GUI Action Mapping table.

Suppose the player's controls are:

Nero MELEE  = Y / TRIANGLE
Dante MELEE = B / CIRCLE

Then:

TAP MELEE

presses Y / Triangle in a [Nero] clip and B / Circle in a [Dante] clip.

Action names such as MELEE, JUMP, LOCK_ON, and DEVIL_TRIGGER make scripts easier to read and follow the player's layout.

Physical button names ignore Action Mapping:

TAP Y

always presses Y / Triangle, even if Melee is assigned to another button.

Character Switcher Clips#

Use [SWITCH] when a macro intentionally changes character and later action names should follow whichever character is current:

[V][SWITCH] Switch route
CHARACTER_SWITCH
WAIT 20
TAP STYLE_ACTION

Normal [Nero] and [Dante] clips continue using their header character's Action Mapping for the entire clip.

CHARACTER_SWITCH requires the Hook's Character Switcher feature to be enabled and ready. The switch is not guaranteed to finish on the same tick, so wait before sending the next character-specific action.

Gamepad Shortcuts#

Enable Gamepad Hotkeys to use controller shortcuts.

Every controller shortcut uses this order:

  1. Hold Back/Select.
  2. While still holding it, press the shortcut button.

Pressing the shortcut button first does not trigger the macro.

Default GUI action shortcuts:

Back/Select + A   Play Macro
Back/Select + B   Stop Macro
Back/Select + X   Capture Snapshot
Back/Select + Y   Load Snapshot
Back/Select + RB  Load Snapshot + Play Macro
Back/Select + LB  Load Setup
Back/Select + RT  Load Setup + Play Macro

A clip may define its own controller shortcut:

[F1][X/SQUARE][Nero] Air route
TAP JUMP

With Gamepad Hotkeys enabled, holding Back/Select and then pressing X / Square starts this clip directly. A matching clip shortcut has priority over a fixed GUI action shortcut.

While Gamepad Hotkeys is enabled, Macro reserves Back/Select and consumes a detected shortcut so the game does not also receive those buttons. The original action assigned to Back/Select, normally Taunt, will not activate manually.

A gamepad shortcut tag may use one accepted name. You do not have to write both controller layouts:

[F1][A][Nero]        Back/Select + A / Cross
[F2][CROSS][Nero]    Back/Select + A / Cross
[F3][B][Dante]       Back/Select + B / Circle
[F4][CIRCLE][Dante]  Back/Select + B / Circle

A slash form is only a readable pair of aliases. Every name in the pair must describe the same physical button:

[A/CROSS]  valid
[CIRCLE]   valid
[L2/LT]  valid
[LT/L2]  valid
[L2/LB]  invalid

Practice Workflows#

Macro GUI#

  • Macro File: choose the loaded macro*.txt file.
  • Macro Clip: choose the clip used by playback actions. Setup-only files do not show this selector.
  • Play Macro: start the selected clip.
  • Stop Macro: stop playback and release macro-held input.
  • Show Macro Playback Overlay: display the current line, next line, held inputs, and progress.

The selected macro file automatically reloads after it is saved, unless playback is currently running.

Keyboard Hotkeys in the GUI run actions on the currently selected file. Load Setup and Load Setup + Play Macro start unbound; use their Set buttons to assign keys. Header hotkeys such as [V][Nero] start the specific clip written in the file.

Macro Playback Overlay#

The playback overlay shows:

Now       current source line
Next      next source line
Held      inputs currently kept active
Progress  clip playback progress

Nero uses a blue palette and Dante uses a red palette. A [SWITCH] clip updates its palette after the current character changes.

Animation Overlay#

Enable System -> Custom HUD elements -> Animation Overlay.

The overlay can show:

Frame    current animation frame / maximum frame
MoveID2  runtime move/action state
Anim     current animation ID
Part     current action phase value
State    grounded, airborne, hitstop, and lock-on flags

Use these values when tuning WAIT_UNTIL ANIM_FRAME, MOVEID2, MOVEID2_CHANGED, GROUNDED, or related conditions.

Show Advanced Animation Fields adds lower-level diagnostic values. Most players do not need them.

Battle Snapshot#

Battle Snapshot quickly restores a practice setup in the same encounter.

Its GUI actions are:

  • Capture Snapshot
  • Load Snapshot
  • Load Snapshot + Play Macro

These actions only use the captured Battle Snapshot. A [Setup] block in the selected macro file does not replace Snapshot behavior.

Normal restore includes:

  • active player position, facing, and velocity
  • camera position and camera parameters
  • matching active enemy positions, velocity, and rotation

Restore Resources additionally restores selected safe resources:

  • player HP and DT amount
  • Nero Exceed level/timer
  • Dante style and supported gauges
  • regular enemy HP and basic stun/displacement data where safe

When Character Switcher is ready, Snapshot records safe resource state for both characters. Loading requests a switch back to the captured active character, waits for the switch to settle, restores the active setup, and restores safe inactive-character resources.

Snapshot refuses a load when the current mission, room, player, camera, enemy count, enemy lifecycle, or captured objects are no longer compatible. This is intentional protection against restoring stale game objects.

Snapshot does not restore every move, projectile, effect, weapon object, enemy AI state, or mission script.

Macro Setup#

A macro file may begin with one [Setup] block before its clips:

[Setup]
Character Nero
Room BP 4
Player 120.0 0.0 -80.0 Face 90
Camera Pos 10.0 250.0 -300.0 Target 100.0 80.0 -50.0 Fov 45
Enemy 1 Frost Pos 200.0 0.0 -60.0 Face 180
[/Setup]

[F1][Nero] Frost test
TAP MELEE

Use Copy Current Setup in the Macro GUI after arranging the room, then paste the copied block before the clips.

Behavior:

  • Macro Setup has its own GUI section below Battle Snapshot.
  • Copy Current Setup copies a ready-to-paste [Setup] block.
  • A file containing only [Setup] ... [/Setup] is valid. Load Setup does not require any macro clips.
  • Load Setup prepares the scene without starting a macro.
  • Load Setup + Play Macro prepares the scene, waits Setup Play Delay Ticks, then starts the selected clip.
  • Play Macro and Load Setup + Play Macro require at least one clip.
  • Character Nero or Character Dante can request Character Switcher before applying the setup.
  • Room ID uses the Hook's room teleport. Room BP moves to that floor when the player is already inside Bloody Palace.
  • Setup waits for the room and its native enemies to become ready.
  • Existing live enemies are matched by type. Missing enemies are generated through the Hook's Enemy Spawn feature.
  • Extra enemies are left in the room.
  • After preparation, Setup applies the listed player, enemy, and camera placement.
  • Copy Current Setup skips dead enemies and cleanup objects that are no longer valid battle targets.

Generated enemies use the current game mode, difficulty, room, and Bloody Palace context. They are normal game-spawned enemies, but Setup does not reproduce every wave-script link, AI state, timer, projectile, effect, or other hidden battle state.

See macro_script_reference.html for every setup field and supported enemy name.

Timing Basics#

WAIT n waits for a number of DMC4 input ticks:

HOLD MELEE
WAIT 1
RELEASE MELEE

A tick is Macro's input timing unit. Do not treat it as an animation frame or a precise number of seconds. When tuning a combo, start with a rough value, test, then adjust while watching the game or the playback overlay.

WAIT_UNTIL waits for a game condition:

TAP JUMP
WAIT_UNTIL GROUNDED
TAP MELEE

If no timeout is written, WAIT_UNTIL uses 120 ticks:

WAIT_UNTIL GROUNDED

is equivalent to:

WAIT_UNTIL GROUNDED 120

Earlier HOLD inputs remain held while waiting. Always release or clear them after the wait:

HOLD LOCK_ON
WAIT_UNTIL ENEMY_STEP 180
TAP JUMP
RELEASE LOCK_ON

TAP sends input; it does not wait for an animation or move to finish.

Some lines create playback time and some do not:

Line typeDoes it advance macro playback time?Example
TAPYes, by its duration. Default is 1 tick.TAP MELEE
WAITYes, by the written tick count.WAIT 10
WAIT_UNTILYes, until success or timeout.WAIT_UNTIL GROUNDED
HOLDNo. It changes held input state.HOLD LOCK_ON
RELEASENo. It changes held input state.RELEASE LOCK_ON
CLEAR / SETNo. They change held input state.CLEAR

That means:

HOLD MELEE
HOLD JUMP
WAIT 1

holds both inputs on the same wait tick, while:

TAP MELEE
TAP JUMP

sends Melee on one tick and Jump on the next tick.

Common Misunderstandings#

If you think...Actual behavior
TAP MELEE waits for the attack to finish.It only sends the input. Add WAIT, WAIT_UNTIL, or another timing command yourself.
TAP JUMP then TAP MELEE is the same as TAP JUMP+MELEE.Separate TAP lines are sequential. + is same-tick input.
HOLD LOCK_ON will release by itself.It stays held until released, cleared, stopped, or playback cleanup runs.
+ means "then".+ means simultaneous input inside one command.
+ only supports two inputs.More inputs are valid when every part is a valid input name.
TAP Y follows Melee mapping.Y is the physical Y / Triangle button. TAP MELEE follows Action Mapping.
MOVE_LEFT is the keyboard A key.It pushes the virtual left stick left.
LEFT is left-stick left.It presses D-pad Left.
[Nero] only checks the current character.It also selects Nero Action Mapping for action names.
Snapshot is a full savestate.It restores supported practice state, not every hidden object or script state.
A [Setup] block replaces Snapshot.Setup and Snapshot are separate workflows.

Troubleshooting#

  • Nothing happens: enable Macro, select a valid file and clip, and confirm that the clip tag matches the current character.
  • The wrong action happens: update Nero or Dante Action Mapping to match DMC4's controller settings.
  • TAP Y ignores Action Mapping: expected. Y is a physical button. Use TAP MELEE when you mean the mapped action.
  • MOVE_LEFT does nothing by itself: it is an input name. Write HOLD MOVE_LEFT, then release it later.
  • Camera does not move: use CAM_LEFT or RS_LEFT. Plain RS presses the right stick button.
  • D-pad action is wrong: LEFT, RIGHT, UP, and DOWN are physical D-pad inputs. They do not inspect Action Mapping.
  • Multi-input TAP fails: use TAP JUMP+MELEE, not TAP JUMP MELEE.
  • Inputs happen together unexpectedly: + means simultaneous. Use separate TAP lines for sequence, or add WAIT for a larger gap.
  • Character-specific actions are wrong after switching: use a [SWITCH] header and wait after CHARACTER_SWITCH.
  • Gamepad shortcut does nothing: enable Gamepad Hotkeys, hold Back/Select first, then press the shortcut button.
  • Back/Select no longer taunts: expected while Gamepad Hotkeys is enabled.
  • Input stays held: click Stop Macro, then make sure every HOLD reaches a matching RELEASE, RELEASE ALL, or CLEAR.
  • WAIT_UNTIL continues without success: its timeout expired. Verify the condition with Animation Overlay or use a larger explicit timeout.
  • Snapshot refuses to load: return to the captured encounter and character state. Recapture after changing rooms, enemies, or major game state.
  • Macro Setup cannot load a BP floor: enter Bloody Palace first.
  • Macro Setup cannot load a room: confirm that the copied Room ID is available in the Hook's Area Jump list.
  • Macro Setup cannot generate an enemy: that enemy type is not supported by the current Enemy Spawn feature. Existing matching enemies can still be repositioned.

Reporting A Crash#

After an unhandled crash, look for:

Devil May Cry 4\dmc4_hook_crashes\<timestamp_pid>\

Send the entire matching crash folder. It can contain:

crash.dmp
crash_report.txt
dmc4_hook_framework_log.txt
dmc4_hook.cfg
macro.txt

Also describe:

  • what you were doing before the crash
  • whether Macro, Character Switcher, Snapshot, or Area Jump was enabled
  • the selected macro file and clip
  • whether the crash is repeatable
