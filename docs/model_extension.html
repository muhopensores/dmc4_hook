Model Extension#

Model Extension adds things to the game's characters and objects without touching their files:

  • Physics chains: hanging, swinging parts such as coat tails, hair, tails, straps (the game's .clt chain files).
  • Extra models: a hat on Nero's head, a jacket over Dante's body, a pouch on a belt. They move with the character and hide when the character is hidden.

You describe what goes where in a small text file (XML). The hook reads it and adds the pieces whenever the character they belong to appears: on every level start and every room change.

Model Extension is in the Debug tab of the hook menu. Tick Model extension to turn it on.

Quick Start#

  1. Put your files (.mod, .tex, .clt, .col) in the game's nativePC folder at the path you want them to have, the same way as any loose-file mod. Example: nativePC\model\game\pl000\my_hat.mod.
  2. Create the folder nativePC\model_ext and in it a file ending in .xml, for example my_hat.xml. You can have as many of these files as you like; the hook reads them all.
  3. Write what you want in it (see the examples below), save it.
  4. In the hook menu, Debug tab: tick Model extension, press Reload lists. Load a level (or change rooms) if the character isn't on screen yet.
  5. The panel shows how many of each piece are out. If a count stays at 0, see Troubleshooting.

Paths: How The Game Names Files#

Every file is named by its game path: the path below nativePC, without the extension. nativePC\model\game\pl000\pl000.mod is model\game\pl000\pl000.

To find the path of a character, open Models in the Model Extension panel: it lists every model the game has loaded since the hook started, each with a Copy button. Some you will see often:

PathWhat it is
model\game\pl000\pl000Nero's body
model\game\pl000\pl000_03Nero's coat (a separate model riding his body)
model\game\pl006\pl006Dante's body
model\game\pl006\pl006_03Dante's coat
Chain files must be named .clt on disk: that is the extension the game asks for. Extraction tools and Albam call the same files .phs; rename them to .clt.

Examples#

A Hat On A Joint#

The hat rides joint 4 of Nero's body (his head; check the number in Albam, see Joint numbers), lifted 5 cm and turned 90 degrees:

<extensions>
  <attach path="model\game\pl000\my_hat" to="model\game\pl000\pl000" joint="4" pos="0 5 0" rot="0 90 0"/>
</extensions>

Clothing Made On The Body#

A jacket modelled and weighted on Nero's own skeleton follows his body joint for joint. No joint= means this mode:

<extensions>
  <attach path="model\game\pl000\my_jacket" to="model\game\pl000\pl000"/>
</extensions>

A Swinging Tail#

A chain on joints of Nero's coat model, colliding with the coat's collision shapes, which sit on his body:

<extensions>
  <model path="model\game\pl000\pl000_03" collision_model="model\game\pl000\pl000">
    <chain clt="model\game\pl000\my_tail" col="model\game\pl000\pl000_03"/>
  </model>
</extensions>

A New Coat With Swinging Tails#

Both together: a new coat follows the body, and its extra tail joints (joints the body doesn't have) swing on chains:

<extensions>
  <attach path="model\game\pl000\my_coat" to="model\game\pl000\pl000"/>
  <model path="model\game\pl000\my_coat" collision_model="model\game\pl000\pl000">
    <chain clt="model\game\pl000\my_coat_tail_l"/>
    <chain clt="model\game\pl000\my_coat_tail_r"/>
  </model>
</extensions>

Reference#

A file has one <extensions> around everything, then any number of <attach> and <model> entries in any order. Paths are game paths (see Paths); upper / lower case and / or \ don't matter.

<attach>: An Extra Model#

SettingNeeded?What it does
pathYesThe extra model (.mod).
toYesThe model it goes on. Every model with this path gets one (both players in co-op, every enemy of that kind).
jointNoA joint number of the to model. With it, the extra model rides that joint rigidly (hats, props). Without it, each joint of the extra model follows the joint with the same number (clothing).
posNoWith joint: an offset in centimetres, "x y z", in the joint's own directions.
rotNoWith joint: a turn in degrees, "x y z", about the joint's X, then Y, then Z.
scaleNoWith joint: one number ("1.2") or three ("1 1 2").
modeNorigid or skin, if you want to say it explicitly.
lineNoAdvanced: the update slot (default 29). Leave it out.

<model> And <chain>: Physics Chains#

SettingNeeded?What it does
<model path>YesThe model the chains hang on. It can be a game model or one of your <attach> models.
<model collision_model>NoThe model the collision shapes sit on (usually the character's body), for all the chains inside.
<chain clt>YesThe chain file (.clt). Its joint numbers are joints of the <model>.
<chain col>NoCollision shapes (.col) the chain bumps into. Needs a collision_model.
<chain collision_model>NoOverrides the <model>'s for this chain.

Making The Files#

Albam (the Blender add-on) imports and exports all of these:

  • A rigid prop (hat, sword, pouch): any .mod. Model it around the origin as it should sit on the joint; pos / rot fine-tune it in the game.
  • Clothing: import the character's body .mod, model the clothing on its armature and weight it to the body's bones, export it as a new .mod. It must use the body's skeleton in the body's rest pose, or it comes out shifted. Extra bones you add (coat tails) get new joint numbers on export and can carry chains.
  • Chains: in Albam, select the bones in Pose Mode, Object Properties > Model Chains > New Chain from Selected Bones, tune, export; rename the .phs to .clt.
  • Collision shapes (.col): Albam's Collision Shapes panel; the shapes sit on the bones of the model you give as collision_model.

Joint Numbers#

Joints are named by number, the number the game uses, which is not the bone's position in a list. In Albam, select the bone: Bone Properties > Game Joint shows it. Chain files store these numbers too.

Rules And Limits#

  • One thing per joint. A joint can be driven by one chain or constraint at a time. Don't give your chain joints that another chain already moves (Nero's and Dante's coat tails), and never joint 0 of a coat model (it attaches the coat to the body).
  • Clothing needs the body's rest pose. Joints with the same number as the body's copy the body's joints exactly; if the clothing was built on a different rest pose it will be offset.
  • Every model with that path. A hat to an enemy's path goes on every enemy of that kind.
  • Edits: after changing an .xml, .mod, .clt or .col, press Reload lists: everything is taken off and put back with the new files.
  • Room changes rebuild everything automatically.

Troubleshooting#

The hook writes what it does to dmc4_hook_framework_log.txt in the game folder. Lines start with ModelExtension:.

You seeLikely cause
The panel lists 0 entriesThe folder or the file name is wrong (nativePC\model_ext\something.xml), the file isn't valid XML (the log gives the position), or the root isn't <extensions>. Press Reload lists after fixing.
Listed, but the count stays 0The to / <model path> doesn't match a loaded model: copy it from Models. Or the character isn't in the level.
"didn't load" in the logThe file isn't at that path in nativePC, or a chain is still named .phs.
A hat floats or is turnedAdjust pos / rot, or check the joint number.
Clothing sits shiftedIt wasn't built on the body's skeleton in its rest pose.
A chain hangs stiff or jittersIts joints are shared with another chain, or it lists a joint 0 of a coat.
A coat lost its attachmentA chain listed the coat's joint 0. Remove it, then reload the level.
